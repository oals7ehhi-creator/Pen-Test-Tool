READY-FOR-REVIEW point. Each item states its **disposition**: fixed, accepted (with rationale), or deferred to a
named later phase. Nothing here weakens a Phase 0 safety invariant.

## 3. Precise scope of the "secret-safe logging" claim

The logger is secret-safe **by construction** in this precise sense: the `event` name must be a registered key;
`fields` come from a closed per-event allowlist of validated scalar validators (iterating the schema's keys, never
the input's); reserved record fields cannot be set from context; and the `correlationId` is constrained to a safe
identifier shape or replaced by a sentinel. There is no field, and no reserved slot, through which a header,
cookie, token, URL, body, or `Authorization` value can be emitted. The claim is **not** that an arbitrary string
is impossible to log — a schema author can still declare a `field.token` slot for a known-safe identifier — it is
that no such slot exists for request/secret data on any current event, and the primitives make adding one a
deliberate, reviewable act rather than an accident.

All five adversarial-review blockers (R-1…R-5) and both evidence gaps (R-6 audit fix, this document) are resolved
in code and proven by tests/CI. The remaining items are either accepted with rationale or explicitly deferred to a
named later phase with no Phase 0 invariant weakened. Phase 1 status stays **READY FOR REVIEW** pending independent
approval.
