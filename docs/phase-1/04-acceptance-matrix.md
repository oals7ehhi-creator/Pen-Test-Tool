`docs/phase-0/06-acceptance-criteria.md`, mapped to the implementation, the tests that prove it, and the CI
gate that enforces it. All paths are repo-relative. CI jobs (`.github/workflows/ci.yml`): **phase0-consistency**,

## 4. Supply-chain integrity of the gates themselves

- Every third-party GitHub Action is pinned to a full commit SHA; every container image (Postgres, Semgrep,
  gitleaks) is pinned by digest (`.github/workflows/ci.yml`).
- SAST runs a **repository-owned** ruleset (`ci/semgrep-rules.yml`) in a digest-pinned Semgrep container with
  metrics/version-check disabled (hermetic).
- The secret-scan gate and its adversarial test run the **same** pinned gitleaks version (8.24.3).

## 5. Coverage

`@pentest/shared` and `@pentest/api` run vitest with `--coverage` and enforce explicit thresholds over their
safety-critical source with **no broad exclusion**:

- shared (`packages/shared/vitest.config.ts`): statements 85 / branches 80 / functions 85 / lines 85.
- api (`services/api/vitest.config.ts`): statements 90 / branches 85 / functions 90 / lines 90. The only
  inline exclusion is the `if (import.meta.url …)` process-entry shim in `server.ts` (a `/* v8 ignore */`
  boot glue whose fail-closed behaviour is itself proven by `boot.test.ts` + `config.test.ts`).

A coverage regression fails the `build-test` job's _Unit tests + coverage_ step.
